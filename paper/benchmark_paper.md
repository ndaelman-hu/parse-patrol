# When the Tools Break: Benchmarking Parser Reliability for Agentic Molecular Science

## Abstract

Agentic systems for the molecular sciences are built on stacks of tools —
parsers, predictors, simulators — that the orchestrating model is assumed to be
able to call reliably. We interrogate the most basic tool in that stack: the file
parser that turns a simulation code's raw output into structured data. We
benchmark four widely used, mature community parsers (ASE, cclib, iodata, and a
custom Gaussian parser), each exposed as a tool through the parse-patrol MCP
server, against 1104 real files from 52 NOMAD entries spanning 16 simulation
codes. Using a field-level success criterion (did the parser actually extract an
atomic structure?) rather than merely "did it avoid raising," we find
catastrophic and systematic failure. On the single primary-output file NOMAD
designates per entry, no individual parser exceeds 23.5% success, and an *oracle*
that picks the best parser per file reaches only 45% — on the remaining 55% no
parser succeeds at all. We further show that a large fraction of failures are
*silent*: parsers return empty-but-valid objects with no exception, which an
agent cannot distinguish from success. We release the benchmark and harness as a
reproducible artifact. Our results are a cautionary baseline: the grounding layer
that agentic molecular-science systems take for granted is far less reliable than
assumed.

## 1. Introduction

Recent work casts large language model systems as co-scientists that plan
syntheses, call domain tools, and close experimental loops. Careful benchmarking,
however, keeps exposing fragility at surprisingly basic tasks. We add a data
point at the very bottom of the stack: **file parsing**.

Every agentic chemistry or materials workflow that reasons over the *results* of
a simulation must first parse those results out of a code's output files. The
community has mature parsers for this — ASE, cclib, iodata — and agent frameworks
increasingly wrap them as callable tools. The implicit assumption is that these
tools "just work": point one at an output file and get structured data back.

We test that assumption directly. We take four parsers exposed as tools by the
parse-patrol MCP server and run each of them over a corpus of real, heterogeneous
computational-chemistry files drawn from the NOMAD repository — the kind of files
an agent would actually encounter. We measure not whether the parser avoided an
exception, but whether it extracted usable scientific content.

The picture is bleak, and interestingly so:

* **No parser is broadly reliable.** On the primary output file of each entry,
  the best single parser succeeds on 23.5% of files; the worst on 5.9%.
* **The failure is real, not an artifact of a naive denominator.** Restricting to
  the file NOMAD itself designates as the main output roughly *sextuples* ASE's
  success rate (3.9% → 23.5%) versus scoring against every file in the upload —
  yet even this fair denominator leaves the majority unparsed.
* **Even a perfect router cannot rescue it.** An oracle that picks the best of
  all four parsers per file solves only 45% of primary files. The parsers that
  succeed are disjoint by domain, so combining them helps — but caps out far
  below usable.
* **Many failures are silent.** The custom Gaussian parser returns a
  structureless model *without raising* on 97.6% of files; iodata and cclib do so
  on many others. An agent receives a well-formed, empty object and no signal
  that anything went wrong.

We release the corpus manifest, harness, and analysis as `benchmarks/` so the
result is reproducible and extensible.

## 2. Related work

Benchmarks of scientific agents have repeatedly found that headline capability
claims outrun measured reliability — tool-augmented agents underperforming on
chemical cost estimation, chemistry LLMs failing symbolic reasoning over
molecular graphs, single-cell foundation models not beating linear baselines. Our
contribution is orthogonal and lower in the stack: we do not benchmark the agent's
reasoning but the *tools* it depends on. To our knowledge, parser reliability
across real, multi-code data has not been systematically benchmarked, despite
being a load-bearing assumption for every downstream agentic result.

## 3. Method

**Corpus.** We use 52 NOMAD entries spanning 16 simulation codes (VASP, Gaussian,
ORCA, GAMESS, exciting, CASTEP, CP2K, ABINIT, Crystal, FHI-aims, GPAW, ONETEP,
NWChem, LAMMPS, Octopus, WIEN2k), comprising 1104 raw files. The entry set,
program metadata, and each entry's NOMAD-designated `mainfile` are frozen into
`dataset.json`; the benchmark is deterministic given that manifest and the files
on disk.

**Parsers.** Four parsers exposed as tools by parse-patrol: ASE (`ase.io.read`),
cclib (`ccopen`/`parse`), iodata (`load_one`), and a regex-based custom Gaussian
parser. Each is called through a uniform `parse(path) -> model` entry point.

**Two denominators.** We report every parser at (i) *all files* — the naive
scenario of pointing a parser at every file in an upload — and (ii) *mainfile
only* — the single primary output NOMAD designates per entry. The gap between the
two separates "failed on files it never claimed to handle" from genuine failure on
the intended input.

**Field-level success.** Every parser's output model uses optional fields, so a
parser may return an essentially empty object without raising. We therefore
define **success** as extracting an atomic structure (atom count plus
coordinates), and track energy extraction as a stricter secondary bar. Each
attempt is labelled `success`, `empty` (no exception, no structure — a silent
failure), `error` (exception; type recorded), or `timeout`.

**Harness.** A manager drives a pool of worker processes, one parse in flight per
worker. Some parsers hang inside C extensions on pathological inputs where an
in-process signal cannot preempt them; the manager enforces a hard per-file
timeout by killing and respawning the offending worker, so a single file is
recorded as `timeout` rather than stalling the run. Parsers are never modified.

## 4. Results

### 4.1 No parser is broadly reliable

**Table 1. Success rate by parser, at both denominators.**

| Parser | All files | Mainfile only | Mainfile w/ energy |
|---|---|---|---|
| ASE | 3.9% (43/1104) | 23.5% (12/51) | 0.0% (0/51) |
| cclib | 15.4% (170/1104) | 21.6% (11/51) | 21.6% (11/51) |
| Gaussian | 2.4% (26/1104) | 7.8% (4/51) | 7.8% (4/51) |
| iodata | 10.5% (116/1104) | 5.9% (3/51) | 5.9% (3/51) |

The mainfile denominator is the fair one, and it is where the assumption "these
tools just work" should hold most strongly — this is the file the simulation's
own metadata flags as the result. It does not hold. Note also that ASE, strong at
*structure* extraction, recovers an *energy* on 0 of 51 primary files: it reads
geometries, not the energetics an agent usually wants.

### 4.2 A perfect router still fails on the majority

**Table 2. Oracle — a file is "solved" if any of the four parsers succeeds.**

| | Solved by ≥1 parser |
|---|---|
| All files | 20.5% (226/1104) |
| Mainfile only | 45.1% (23/51) |

On 28 of 51 primary files, **no parser succeeds**. And the parsers that do
succeed are nearly disjoint by domain:

**Table 3. Which parser set solves each mainfile.**

| Winning parser set | Mainfiles |
|---|---|
| *(none — no parser succeeds)* | 28 |
| ASE only | 12 |
| cclib + Gaussian | 4 |
| cclib only | 4 |
| cclib + iodata | 3 |

ASE wins on materials/structure codes (VASP, FHI-aims, GPAW); the
cclib/iodata/Gaussian family wins on molecular quantum chemistry (ORCA, Gaussian,
GAMESS, NWChem). They never co-succeed on a mainfile outside the molecular-QC
cluster. A multi-parser router is therefore *necessary* — no single tool spans the
domains — but even the union of all four leaves most files unparsed.

### 4.3 Failures are often silent

**Table 4. Outcome breakdown (all files).**

| Parser | Success | Empty | Error | Timeout |
|---|---|---|---|---|
| ASE | 43 | 0 | 1061 | 0 |
| cclib | 170 | 39 | 849 | 46 |
| Gaussian | 26 | 1077 | 0 | 1 |
| iodata | 116 | 163 | 825 | 0 |

The `empty` column is the dangerous one. The custom Gaussian parser raises *no
exceptions at all*: on 1077 of 1104 files it returns a structureless model that an
agent will happily accept as a successful parse. iodata (163) and cclib (39) do
the same on many files. A tool that fails loudly can be caught and routed around;
a tool that fails silently corrupts everything downstream of it. This is a
concrete, measurable hazard for agentic pipelines, which typically check for
exceptions, not for empty payloads.

### 4.4 Failure taxonomy

The dominant failure mode across parsers is **format not recognized**. For ASE:
`UnknownFileTypeError` (39%), `StopIteration` (21%, typically empty/malformed
files), `ValueError` (16%), `UnicodeDecodeError` (13%, binary files fed to a text
parser). For cclib, 94.7% of exceptions are the "unrecognized format" signal
(`ccopen` returning `None`); for iodata, 97% are `FileFormatError`. This ASE
breakdown closely reproduces an earlier independent ad-hoc stress test of the same
parser on NOMAD data, which is a useful external check on the harness.

## 5. Discussion

**Implications for agentic molecular science.** The grounding step is a silent
bottleneck. A retrosynthesis planner or property predictor that ingests
simulation output is, in the common case, ingesting nothing — either an exception
it may not handle, or worse, an empty object it mistakes for data. Three concrete
takeaways:

1. **Wrap parsers with a content check, not just a try/except.** The `empty`
   outcome shows exception-handling alone is insufficient; tools must assert that
   scientific content was actually returned.
2. **Route by code, and expect gaps.** Success is strongly code-dependent and the
   winning parser differs by domain, so a capability-aware router over multiple
   parsers is the right architecture — parse-patrol's multi-parser design is a
   natural substrate. But Table 2 bounds how much routing can buy: 45% on primary
   files. The remaining gap needs new parsers or format-hinted parsing, not just
   better selection.
3. **Report the denominator.** Naive "point it at everything" success rates
   understate parsers dramatically (ASE 3.9% vs 23.5%). Evaluations of tool
   reliability must state what set they score against.

## 6. Limitations

The corpus is a single snapshot of NOMAD (52 entries, 16 codes); success is
defined by field presence, not correctness against ground truth (a parser that
extracts a *wrong* structure counts as success here); we evaluate parsers with
default settings and no format hints, which is the agent's default but not the
expert's; and we deliberately do not run a live LLM agent loop — this paper
benchmarks the tools, not an agent's ability to orchestrate them. Each is a clear
direction for follow-up.

## 7. Conclusion

The parsers underneath agentic molecular science are far less reliable on real,
heterogeneous data than their adoption assumes. On the primary output files of a
16-code NOMAD sample, the best single parser succeeds on under a quarter, a
perfect router on under half, and a large share of failures are silent. We offer
this as a rigorous negative baseline and a reusable benchmark for the reliability
of the tools that agentic systems are built on.

## Reproducibility

All numbers are produced by the `benchmarks/` package in the parse-patrol
repository:

```bash
uv run python -m benchmarks.dataset  # freeze corpus -> dataset.json (networked)
uv run python -m benchmarks.run      # parse everything -> results.csv (offline)
uv run python -m benchmarks.report   # aggregate -> report.md
```
